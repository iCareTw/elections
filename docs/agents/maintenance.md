# 制度檔維護協議（maintenance）

管的是這些檔案：`CLAUDE.md`、`docs/agents/*.md`、`.claude/agents/verifier.md`。

## 可以自行改（不需先問 user）

- 修正錯字、失效的路徑、已改名的工具或指令。
- 在 judgment.md 的「踩坑紀錄」追加新教訓（格式見下）。
- 更新 dispatch.md 的 agent 清單以符合當下環境實況（改前先用 system-reminder 的實際清單核對）。
- 補充範例（正例/反例），前提是不改變規則本身的意思。

自行改也要遵守：改前備份到 `docs/drafts/{檔名}.{日期}.bak`，改完在回覆中告知 user 改了什麼。若 user 當下的訊息正好在討論同一處（尤其是混合語氣的訊息），先照 CLAUDE.md 的「諮詢優先於執行」處理，不要邊討論邊改。

## 動之前必須先問 user

- 刪除或放寬任何規則（尤其：DB 兩步驟、驗證不自驗、諮詢優先於執行）。
- 改變溝通偏好相關規則（首答精簡、user 觀點）——這些是 user 的明示偏好。
- 改 `CLAUDE.md` 的專案目標、命名規範、產品邊界。**type enum 值、region 名稱等資料字面值，即使看起來像錯字也要先問**（那可能是官方正式寫法）。
- 大幅重組檔案結構（合併、拆分、搬移 docs/agents/ 下的檔案）。

## 踩坑後教訓寫回哪裡

| 教訓類型 | 寫到哪 |
|---|---|
| 判斷錯誤（該問沒問、該停沒停、方向錯了沒發現） | `judgment.md` 末尾「踩坑紀錄」段（不存在就建立） |
| 派工失敗（prompt 缺什麼、model 選錯） | `dispatch.md` 對應節，直接修規則或補判準 |
| user 給的糾正與偏好 | auto-memory（`~/.claude/projects/.../memory/`）新增 feedback 檔＋更新 MEMORY.md 索引 |
| 環境陷阱（工具行為、設定問題） | `00-diagnosis.md` 的「次要發現」段 |

**格式**（一條一行，可加正/反例）：

```
- 2026-07-06｜情境：{一句話}｜錯誤：{做了什麼}｜改為：{以後怎麼做}
```

**去重**：寫入前先看該檔有沒有同義條目，有就合併強化，不新增重複條。

## 精簡門檻

- 任一制度檔超過 **160 行**，或踩坑紀錄超過 **10 條**：下次觸碰該檔時先精簡——把重複條合併、把已內化成正式規則的紀錄刪掉（規則本身留下）。
- CLAUDE.md 超過 **90 行**：把細節下放到 docs/agents/，CLAUDE.md 只留規則一句話＋指向。
- 精簡是「合併與下放」，不是刪除規則；要刪規則回到「必須先問 user」。

## 每季健檢（或 user 要求時）

1. 逐檔 grep 檢查引用的路徑、工具名、agent 名是否仍存在。
2. 核對 dispatch.md 的可用 agent／model 清單與當下環境是否一致。
3. 檢查 auto-memory 的 MEMORY.md 與 docs/agents/ 有無互相矛盾（memory 記的是舊決定時，以較新者為準並更新舊的）。
